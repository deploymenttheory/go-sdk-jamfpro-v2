# Jamf Pro 11.32.0 API delta

Spec PR: #221. Baseline: `11.31.1-t1787060595569`; target: `11.32.0-t1787580540993`.
The baseline is the immediate previous available release, not main's latest spec (11.33.1).

Reproduce the structural comparison:

```sh
python3 scripts/openapi_delta.py openapi-specs/11.31.1-t1787060595569/api-schema.json openapi-specs/11.32.0-t1787580540993/api-schema.json
```

The complete structural output is in `11.32.0.diff`. Descriptions, examples, summaries,
operation IDs and tags are excluded from that output; validation, privileges and
extensions are retained.

Classic `swagger.yaml` also changes: GET/PUT `/activationcode` are marked deprecated
as of 2026-07-14. The SDK retains both methods and adds deprecation comments.

## SDK changes

- Computer inventory v3/v4: nullable `appleEnrollmentType`, `awaitingConfiguration`,
  and `lockdownModeEnabled` fields. Pointers distinguish uncollected data from false.
- Account preferences v3: `showDirectoryGroupUuidColumn`, including false in serialized updates.
- Mobile inventory: enrollment fields, return-to-service, lockdown mode, and component
  system health in the applicable existing detail models. Nullable values use pointers.
- Notifications: `DeleteV1` dismisses notifications for the current user and site.
- Existing SSO settings service: broker configuration GET/PUT wrappers, separate request
  and response models, with credentials excluded from response models.
- Accounts: accept the added `MIGRATED` account type.

`InventoryListMobileDevice` / `InventorySelectionListMobileDevice` changes refer to
v1 mobile list schemas, which this service does not expose; v2 basic records did not
return those fields, so they are not added to that model.

tokens, tenant URL, or original identifying computer records are committed.

One temporary mobile device was created with a unique test serial and deleted
successfully (HTTP 200). Classic API creation returned 201 with a non-JSON body
despite the JSON Accept header; lookup by the unique serial recovered its ID.

The captured fixtures contain the relevant curl response fields; unrelated identifying
fields were removed. Populated boolean/enrollment variants in unit tests are synthetic.
Mobile iOS component values, populated return-to-service and lockdown status, migrated
account writes, and successful broker GET/PUT remain unverified live. Broker updates
were not sent because this tenant has no broker configured and changing SSO would
exceed the limited write-test authorization. Their models follow the candidate delta;
no successful live behavior is claimed for these cases.
