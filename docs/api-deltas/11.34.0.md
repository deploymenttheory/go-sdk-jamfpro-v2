# Jamf Pro 11.34.0 API delta

Spec PR: #235. Immediate predecessor: `11.33.3-t1793127642444`.
Target: `11.34.0-t1793383479089`.

`11.34.0.diff` records the complete REST structural comparison, excluding documentation
text, examples, operation IDs and tags. `11.34.0-classic.diff` records the Classic
Swagger comparison. The comparison helper is included in SDK PR #237.

## Changes and disposition

| Delta | SDK disposition |
| --- | --- |
| Three action-log GET endpoints | New ActionLogs service: list, detail and device outcomes; pagination/filter forwarding |
| Directory-cache status and targeted group/user sync | New DirectoryCache service with nullable status fields and query-based POST methods |
| Active sessions/count v2 | Added versioned methods and response models; count uses `activeUserCount`, as returned by curl |
| Fresh FedRAMP initialization v2 | New request model and method on existing initialization service |
| Available updates adds tvOS/visionOS | Added lists to the existing response model |
| Managed updates adds VISION_PRO | Added device/status constants; existing string fields accept it |
| Groups adds divisionId | Nullable response field on existing group model |
| Compliance registrations and grace-period state | Added response objects with nullable user IDs, duration and timestamps |
| ReturnToService.shouldRetryEnrollment | Optional boolean pointer preserves explicit false and omission |
| UserAccount.ropfMigrationScope | Added response/request field; no speculative enum rejection |
| Enrollment QuickAdd signing/certificate fields become read-only/deprecated | Annotated existing fields, retaining compatibility |
| macOS branding applicationName maximum becomes 44 | Documented server constraint; no unverified client-side validation added |
| v1 inventory collection settings/custom paths removed | Service already uses v2; no SDK route change needed |
| Preview remote administration routes removed | No implemented SDK operations use these paths |
| v2 account preferences removed | Existing SDK uses v3; no route change needed |
| Deprecation replacement metadata on existing REST endpoints | Recorded completely in structural diff; no automatic rerouting of versioned methods |
| Classic activation-code/computer replacement metadata | Recorded in Classic diff; no methods removed or redirected |

The removed schemas belong to the removed routes above. No currently used SDK
response type is deleted. These changes are additive to existing callable methods.

## Verification limits

Directory-cache sync writes and fresh FedRAMP initialization were not sent to the
live tenant. Only one temporary mobile record and dismissal of empty notifications
were authorized for write testing. The write wrappers follow candidate spec deltas
and have unit coverage for endpoint/query handling, success, validation and errors;
successful live behavior remains unverified. Successful compliance registration and
migration-scope writes likewise require suitable tenant data and separate validation.
No MDM erase or enrollment workflow was triggered to test retry enrollment.

New acceptance checks use an inclusive minimum-version gate: the existing
strictly-greater helper skips 11.34.0 itself. Existing checks keep their semantics.

The read-only SDK acceptance tests cover all action-log reads, directory sync status,
and v2 session reads. Full unit-suite and acceptance execution results are recorded
in the PR. Existing CI runs unit tests, lint, dependency review and CodeQL.
